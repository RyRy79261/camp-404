# Importer (#239): recipes, logistics data and inventory, uploaded into the app

Status: proposal, waiting for the owner. Nothing is built.

## Rules

- **Only recipes, logistics data and inventory. Never people's data**
  (owner, 2026-09-23): no names, contacts, ID, bank, money, dietary or
  medical details, and nothing tied to a person.
- **Nothing outside the app** (owner, 2026-09-27). The files are **uploaded
  into the app** by a captain or the team's lead. The app never reads Google
  Drive, Sheets or Notion, and holds no credentials for them.
- **No operator steps against production.** #239 as written is a command in
  `apps/admin-cli` run against the database by hand. That breaks the rule
  that nobody runs a CLI against production. So the importer becomes a page
  in the app; the CLI version is dropped.

## What files, and where they come from

A captain or lead exports the old sheet on their own computer and uploads it.
Formats: `.csv` and `.xlsx` (one sheet at a time). Markdown export for Notion
pages if needed.

| Import        | Old source                                                                                                                                            | Goes into                                                             | Who uploads                     |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------- |
| **Recipes**   | Last burn's kitchen workbook (menu + ingredient lines per meal); the Notion kitchen databases (≈31 recipes, 125 ingredients, 257 lines) as CSV export | a recipe **source** per recipe (`recipe_sources`), status `suggested` | captain or Kitchen lead         |
| **Inventory** | The storage inventory sheet (by category), kitchen equipment need/have                                                                                | `inventory_items` and `inventory_needs` (PR #300)                     | captain or the item team's lead |
| **Logistics** | The pack / unpack / strike schedule                                                                                                                   | `camp_events` (the calendar proposal, #247)                           | captain                         |

Recipes land as **sources**, not finished recipes: the kitchen then sends each
to Claude for proofreading, at a lead's click, as today. The importer never
starts a Claude run. Method steps were never in Notion (they were in a
separate "Cook Book" document), so those recipes arrive without steps until
someone pastes them in.

## How the upload works

1. **Pick the import and the file.** The file is read on the server, in
   memory, and **never stored** (like the bank statement import in PR #299).
2. **Check the headers first.** Each importer has a fixed list of columns it
   takes (no guessing). If the file has a column on the **deny list**, the
   whole file is refused, naming the column: names of people, email, phone,
   Telegram, ID or passport, bank, account, IBAN, SWIFT, reference, medical,
   allergy, dietary notes about a person, payment, fee, paid, received,
   "shopper", "bought by". Unknown columns are dropped and listed.
3. **Free text is dropped**, not scanned: notes and "who is buying" columns
   are not carried over unless the importer has an explicit rule for them
   (for example a recipe's cooking notes, after a lead reads them).
4. **Preview.** The page shows what would be created, what already exists
   (matched by name + year, so a second upload adds no duplicates) and what
   was dropped and why. Nothing is written yet.
5. **Confirm.** One transaction writes the rows, each stamped with its source
   ("imported from the 2026 kitchen workbook") and an audit row. The page
   lists imports so one can be undone as a whole.

Quantities: take each line's base quantity and unit only. Units outside the
app's list (`RECIPE_LINE_UNITS`: g, kg, ml, tsp, ...) such as "cans" or
"bricks" stay in the source text for Claude to settle. Prices and product
links are not imported. Totals are always worked out in code.

## Tests it needs

- Each deny rule refuses its header (then remove the rule and watch the test
  go red).
- Notes columns are dropped.
- A second upload of the same file creates nothing.
- Imported recipes are `suggested` with no proofreading run queued.
- Fixtures are invented; no real export is ever committed.

## Build order

Each importer after its target exists: **inventory** first (PR #300 has the
tables), **recipes** next (sources exist on main), **logistics** after the
calendar events table (#247).

## Questions for the owner

1. **An upload page in the app instead of the admin CLI**, because the CLI
   would be a manual step against production? _Default: yes._
2. **Which old files are there?** The kitchen workbook, the Notion kitchen
   export, the storage inventory sheet and the pack schedule. Any others?
   _Default: those four only._
3. **Recipes arrive as sources for the kitchen to proofread** (not as
   finished recipes)? _Default: yes._
4. **Who may import:** captains for everything; a team's lead for their
   team's inventory; Kitchen leads for recipes? _Default: yes._
5. **Keep per-recipe "lessons" notes from Notion** (after the burn: time
   taken, what changed), with names stripped, as notes on the recipe?
   _Default: yes, shown to a lead in the preview before they are saved._

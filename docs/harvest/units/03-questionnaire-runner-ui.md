### 10 — the aggregator, in enough detail to start

`AggregateBase = { questionId, prompt, questionKind, responded, skipped, total }`. Denominator rule to keep verbatim: percentages are **of respondents who answered that question**, not of everyone sent it (`:27-28`). Digits: `pct(c,d) = d<=0 ? 0 : Math.round((c/d)*1000)/10` (one decimal); `average = n===0 ? null : Math.round((sum/n)*100)/100` (two). Union is 7 arms discriminated on `chart`: `choice{options:OptionTally[], other:OtherTally[]}`, `scale{min,max,minLabel,maxLabel,buckets:ScaleBucket[],average}`, `rating`, `boolean{yes,no,percentYes}`, `text{answers:string[]}`, `timeline{buckets,earliest,latest}`, `grid`. Plus `orphans: {questionId,count}[]` — answers whose question was deleted; Camp 404 reaches this state routinely because `classifyChange` only version-bumps, so response rows survive definition edits.

Re-map onto Camp 404's 14 kinds (`packages/types/src/questionnaire.ts:207-223`), corrected from the digest: `toggle` and `combobox` carry the identical `options:{value,label}[]` shape as `single_select` and drop straight into the `choice` arm with **no new code**; `scale` needs only a field rename (`steps`, not `options`). Genuinely new arms are needed for exactly **two** kinds — continuous `slider` (spec §7.2's min/max/avg/median numeric summary) and `number` (§7.2 puts it under histogram; the donor has no such kind). Drop the `grid` and `rating` arms entirely, and drop `other`/`OtherTally` — `isOtherAnswer`/`otherAnswerText` do not exist in Camp 404. **Deliberate divergence from the donor:** §7.2's PII rule means the `text` arm returns a *count*, never `answers: string[]`, and `email`/`phone`/`image`/`date`/`short_text`/`long_text` are all count-only. Keep the deleted-option-still-gets-a-row behaviour (`:211-219`). Port `questionnaire-results.test.ts` (341 L) with it — the verifier flagged that neither original agent mentioned it, and it pins every rounding and denominator decision.

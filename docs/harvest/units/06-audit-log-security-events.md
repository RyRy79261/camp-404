### Technical substance

**`writeAuditEvent`.** Take the *suppliers* copy, not the org one — only it is typed `DbOrTx` (`apps/suppliers/lib/audit.ts:14`) and its comment says that is deliberate so it composes inside multi-write actions. The body is five lines: `db.insert(schema.auditEvents).values({actorId, action, subject: subject ?? null, meta: meta ?? null})`. Renames: `subject`→`target`, `meta`→`metadata`. **Blocker the digest understated:** camp404's column is bare `metadata: jsonb("metadata")` (`schema.ts:1188`); a `metadata?: Record<string, unknown>` parameter will not typecheck until you add `.$type<Record<string, unknown>>()` — a type-only edit drizzle-kit emits no migration for, but it must land with the helper. Also note `createHttpDb` has **no** interactive transactions (AGENTS.md:70-75), so the `DbOrTx` signature only pays off for callers already on `createPooledDb`. Add `"./audit": "./src/audit.ts"` to `packages/db/package.json` (24 subpath exports today, lines 9-33).

**The disclosing-read pattern.** Donor `resolveMedicalNotesForViewer` makes four moves. Camp 404 **already has move (a)**: `requireCaptain()` at `actions.ts:142` runs before `getCampMemberDetail()` at `:145`, so ciphertext is never loaded on a refusal — I checked, and the digest overstated this as missing. The three genuinely missing moves: **(b) three-state result** `{visible, value, unreadable}` — `decryptOrNull` (`packages/db/src/crypto.ts:72-76`) collapses "no ID on file" and "ciphertext we cannot decrypt" into the same `null`, so a broken key currently renders as "this member gave us nothing"; **(c) audit only a real disclosure** — `if (!isSelf && value)`, since reading your own data is not an access event and an empty field discloses nothing; **(d) write in `after()` from `next/server`** with `catch (err) { console.error(...) }` — **logged, not swallowed**, which is the point: a silently swallowed catch makes an unread trail undetectable. `after()` is imported nowhere in camp404 today, so this introduces the convention. Store the authority on the row: `metadata: { basis }` over a small union — `"self" | "captain"` now, `"team_lead"` once WP6 #130 gives `team_memberships` a write path.

**PII-access log reader.** Port verbatim from `medical-audit.ts`: `LOOKBACK_DAYS = 30` (:28), `ROW_CAP = 500` (:31), `Math.min(options.limit ?? CAP, CAP)` (:122-125), `truncated = rows.length >= limit` (:186), the `UUID_RE` guard (:33-34) filtering the **second** name-resolution query — camp404's `target` is also `text`, same trap, and casting it in a join lets one malformed row error the whole page — and `parseBasis`'s allow-list over untrusted jsonb (:59-66; its test seeds `"because I said so"` and asserts `null`). Above all keep the fail-closed `throw new Error("Not authorised…")` (:113-120) with its comment: there is no redacted version of these rows, because a row only exists when the subject *has* an ID on file, so the list is a census. The permission collapse is one line: `canReadPersonalInformationIn(actor, "audit")` → `hasClearance(rank, "captain")` (`packages/core/src/access.ts:25`).

**`privacy.ts` (the verifier caught this, and it is right).** The donor's own AGENTS.md says the privacy classes are "both enforced in `@quagga/core` privacy.ts, NEVER in the UI". Porting the prose without the module leaves you with a rule and nothing that fails a build. The shape: `HARD_LOCKED_PRIVATE_FIELDS` (no access path of any kind) + `SAFETY_VISIBLE_FIELDS` (visible to the audience consented to at entry) + `ALWAYS_PRIVATE_FIELDS` as their union, all `as const` string tuples with derived types and a `ReadonlySet` for lookup — 127 lines total, ~40 for a camp404 version over the ID/passport/EFT/emergency-contact set. It is what makes a projection test *derived from the constant* rather than hard-coding one key name; the donor rewrote its own after admitting the earlier version "named itself the projection regression and protected nothing" (`medical-access.test.ts:174-176`). Camp 404's live target is `PublicRosterRow` vs `RosterRow` (`apps/web/lib/camp-roster.ts:21,41`).

**Table + Skeleton.** `packages/ui/src/lib/utils.ts` is **byte-identical** across the two repos (`diff` produced no output), and `table.tsx`'s only non-React import is `cn` from it — a true drop-in. Keep `TableCaption` with `className="sr-only"`: it exists because a screen reader announced "table" twice on the one page whose whole purpose is answering "who saw my ID number?" (`medical-access-panel.tsx:110-118`), and the donor e2e then scopes assertions by that accessible name. ## DB changes this unit implies

- `audit_log.metadata` → `.$type<Record<string, unknown>>()` (type-only; no migration emitted, but readers need it or every row reads back as `unknown`).
- New index `audit_log_target_idx` on `target` — "what happened to this member".
- New index `audit_log_created_at_idx` on `created_at DESC NULLS LAST` — every reader in this unit does `ORDER BY created_at DESC LIMIT n`. The donor added both in migration 0024 *after* finding three hot readers scanning the whole table.

## Corrections applied

- **`getAuditTrail` conditional projection (REFUTED).** The donor's `...(personal ? { actorEmail: schema.users.email } : {})` idiom has **no camp404 analogue**: `users` has no email column (`packages/db/src/schema.ts:249-290` — I confirmed: `displayName`, `passportEncrypted`, `saIdEncrypted`, `eftDetailsEncrypted`, `inviteCode`, no email). Identity email lives in Neon Auth. The only actor label is `users.display_name`, already public on the roster. So the projection degenerates to an unconditional select, and the "Unknown actor" fallback becomes load-bearing (display_name is nullable) rather than cosmetic. What survives is the one-line `ne(action, DISCLOSING_READ)` WHERE-clause exclusion. **Re-rated effort M → S.** Same correction applies to `getRecentActivity`.
- **`AuditTrailList` as a "forcing function" for status tokens (REFUTED).** Camp 404 already shipped `--color-success` / `--color-warning` (`globals.css:49-52`) and the Badge variants. It is a two-line retoken, easier than claimed, and levers nothing.
- **`after()` catch is "swallowed" (REFUTED).** It is `console.error("[medical-access] audit write failed", err)` (`apps/web/lib/medical-access.ts:88-90`) — I read it. Logged, not swallowed, and that is the whole point.
- **"Authorise then select" is missing in camp404 (my own correction).** It is not. `requireCaptain()` runs before `getCampMemberDetail()` at `actions.ts:142-145`. Only the audit row and the three-state result are missing.
- **`assertCron` is "byte-equivalent"** — false. camp404 compares the whole header against `Bearer ${secret}`; the donor slices the prefix and accepts two env names. Same properties, different code, nothing to port.
- **`cancelPendingDeletion` same-transaction audit at effort S** — half true. `acceptCaptainPromotionAction` (`apps/web/app/notifications/actions.ts:79-83`) records that its two writes are deliberately non-atomic-but-idempotent "because the Neon HTTP driver has no interactive transaction". Adopting the same-tx half means moving that action to `createPooledDb`. The WHERE-status guard alone is the S-sized piece.
- **Digit fixes:** camp404 has 41 non-story UI components (not 40) and 28 pgEnums (not 29); the donor's `ACTIVITY_LABELS` holds 32 entries (not 34); camp404's Security/POPIA section is **three** bullets (not five) — I confirmed at `AGENTS.md:184-191`; eight *source* files hand-roll date formatting (the ninth is a test).

### `.gitattributes` — the whole substance
Copy the donor file, change one digit and drop one line. Content: a ~24-line comment, then `*.pen -merge`, `design/brand/** binary` (**drop** — no such dir), `* text=auto eol=lf`, `*.png binary`, `*.jpg binary`, `*.ico binary`. The comment's argument is the value: a line-level merge of a node tree gives *structurally valid JSON that is semantically wrong* — duplicated node ids, a frame carrying children from two versions, geometry from one edit against content from the other; Pencil opens it looking almost right. `-merge` makes git stop with "both modified". Diffs stay ON deliberately. **Change the digit:** the donor comment says "173k lines of pretty-printed JSON" — Camp 404's `design/app.pen` is 45,390 lines / 1.6 MB (measured). `git check-attr -a design/app.pen` currently returns nothing.

### Security headers — the correction matters more than the port
`apps/web/vercel.json:10-25` already sends four: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(self), microphone=(self), geolocation=()`, `Content-Security-Policy: frame-ancestors 'none'`. Genuinely missing: `X-Frame-Options: DENY` and `Strict-Transport-Security: max-age=63072000; includeSubDomains`. **Do not copy the donor's Permissions-Policy** — its `camera=(), microphone=()` would break `apps/web/components/voice/use-voice-recorder.ts` (confirmed `getUserMedia` caller) and avatar capture. **Do not add a `headers()` key to `next.config.ts`** — that creates a second competing header source. Add the two pairs into the existing `vercel.json` array. Keep the donor's stated reason for *not* writing a full CSP: a strict `script-src` needs per-request nonces through Next's inline bootstrap, and getting it subtly wrong white-screens the app.

### Coverage ratchet — the shape, not the 8-shard matrix
Skip the donor's 8-shard coverage CI matrix (enterprise machinery for a 97-file suite). Take the workspace configs. Each donor config carries: `coverage.provider: "v8"`, `reporter: ["text","json-summary","json"]`, `reportOnFailure: true`, an `include` that counts *every* source file rather than only imported ones (so the % describes the package, not the run), global `thresholds` annotated with the measured run they came from, and `thresholds["path/to/file.ts"] = {lines:100,statements:100,functions:100,branches:100}` for pure privacy predicates. Standing comment to carry verbatim into all 8: *never lower a floor to make a build pass — the drop is the signal, and lowering the floor deletes it.* Camp 404's 100%-floor candidates (all pure, all with sibling tests in `packages/core/src/__tests__/`): `packages/core/src/text-redaction.ts`, `access.ts`, `id-validation.ts`, `promotion.ts`, plus `packages/db/src/crypto.ts`. **Two traps.** (a) `apps/web/vitest.config.ts:13-17` aliases only `@` — at least 20 modules under `apps/web/lib/` `import "server-only"` and will throw the instant a `coverage.include: ["lib/**"]` pulls them into the denominator; add a `server-only` stub alias first (the donor does this at `apps/web/vitest.config.ts:92-100`). That blocks `apps/web/lib/account.ts` and `camp-roster.ts` until it's done. (b) Scope apps to `lib/**` only — the donor measured `app/**` + `components/**` at ~3% and threw the number away as "a figure that describes the test RUNNER rather than the code". Also move `outputs: ["coverage/**"]` off the plain `test` task (`turbo.json:45-47`, where nothing writes it) onto a new `test:coverage` task.

### Label taxonomy — port 28 unchanged, substitute 8 areas
Donor `GITHUB_LABELS` (`packages/core/src/report.ts:162-345`) is **35** labels, not 34. Port unchanged: 7 `type:` (bug/feature/enhancement/docs/chore/copy/design), `needs-triage`, 5 `status:` (needs-info/in-progress/blocked/wontfix/duplicate), **4 `priority:`** (critical/high/medium/low — the digest's original ADAPT silently dropped these, and both `issue-forms.test.ts` assertion 6 and the triage contract depend on them existing), `auto-triaged`, `needs-human`, 2 `agent:` (ready/in-progress), `source: in-app`, and the 6 generic areas (questionnaires, notifications, auth, privacy, data, ui). Delete the 3 `app:` labels (three-app split). Substitute 8 Camp 404 areas for the 4 AfrikaBurn ones: roster, teams, invites, builder, mcp, telegram, push, family-tree. Shape is `{name, color /* 6 hex, no # */, description}`. Hard limits, enforced by the test file below: description ≤ 100 (GitHub 422s), `/^[0-9a-f]{6}$/`, name ≤ 50, no duplicates. `syncGithubLabels()` copies verbatim — global `fetch` only, two load-bearing details: `encodeURIComponent(label.name)` in the GET probe (names contain a space *and* a colon; unencoded, every PATCH silently becomes a POST) and collect-failures-then-report (`{created, updated, failed:{name,status}[]}`) rather than aborting on the first bad label. Labels not in the list are left alone — which matters, because the repo already carries `bug`/`enhancement`/`from-app` on live issues.

**The real decision hiding in here:** Camp 404's reporter lets a report state its own priority. `feedback-ai.ts:20` has a `severity` field the AI infers from the reporter's prose (prompt at `:63` calls it "a rough triage hint from the description alone") and `github-feedback.ts:122` renders it as `_Severity hint: <severity>_` — the first line a triager reads. The donor deliberately removed exactly this field, with the rule *"priority is one wiring mistake away from being a permission"*. Keep it or kill it, but decide consciously.

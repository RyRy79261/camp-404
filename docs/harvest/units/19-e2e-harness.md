### 1. `appAlerts` — the whole file
```ts
export function appAlerts(scope: Page | Locator): Locator {
  return scope.locator('[role="alert"]:not(#__next-route-announcer__)');
}
```
That is the entire donor module minus its doc-comment. Next injects `<div role="alert" aria-live="assertive" id="__next-route-announcer__">` into every page, so `getByRole("alert")` can never resolve to one element and `toHaveCount(0)` can never pass — in any Next app. Camp 404 already discovered this (comment at `signup.spec.ts:33-35`) but works around it with `page.getByRole("alert").filter({ hasText: /isn't valid/i })` at `signup.spec.ts:36-38` and `invite-tracking.spec.ts:154-156`. That form can only assert an alert IS present with known copy — it cannot express "no error was shown", which is the assertion the enumeration spec (#4) and the negative-path suite need. Copy verbatim, retarget the two call sites.

### 4. Enumeration-safe sign-in

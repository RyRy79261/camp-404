# 01 — questionnaire-engine

**Headline:** The donor is a downstream fork of Camp 404's own spine (`packages/types/src/questionnaire.ts:2` reads "Ported from the Camp 404 questionnaire spine"), so this is a re-merge, not a graft — take the **results aggregator** (Camp 404 has literally zero results code), the **coded `DefinitionIssue` model**, and four **effort-S** fixes that close a live answer-smuggling hole and make a default questionnaire send actually reach someone.

**Camp 404 today:** The builder is shipped end-to-end — types (`packages/types/src/questionnaire-builder.ts`), 7 DB tables, lifecycle (`packages/db/src/questionnaire-lifecycle.ts`), captain canvas (`apps/web/app/captains/questionnaires/[key]/`), runner (`apps/web/app/questionnaires/[activationId]/`) — with per-block/per-page `visibleIf` branching (10 ops) rather than the donor's per-option `goTo`. What is absent, verified: no results/aggregation/CSV/metrics code anywhere (`ls apps/web/app/captains/questionnaires/[key]/` → only `preview` and `send`), no per-respondent viewer, no non-blocking delivery surface, no `other:`/format on text answers, no frozen backward-compat fixture.

### 1. Hidden-field smuggling (start here — it is 5 lines and it is a hole)

`validateBuilderResponses` (`packages/types/src/questionnaire-builder.ts:277-310`) is branch-aware and correctly skips required checks for hidden fields, but then does, verbatim at :296-298:

```ts
if (hidden) {
  // Retain any previously-entered value untouched; do not validate.
  if (data[id] !== undefined) responses[id] = data[id];
  continue;
}
```

`data` is `QuestionnaireResponses.safeParse(raw).data` — the **client payload**, not a DB read-back. On final submit a respondent can post any `string|number|string[]|boolean|null` under a hidden field's key and it is stored. Worse: every **non-final** save skips the validator entirely — `apps/web/app/questionnaires/[activationId]/actions.ts:73-75` sets `toStore = responses` (the whole raw record, arbitrary keys included) and upserts it. The donor's stated property is "answers to skipped questions can't be smuggled into the stored response." Decide retain-vs-drop deliberately (retain is friendlier on back-nav; drop is safe), write it into `docs/questionnaire-builder.md §5`, and if drop wins it is one `continue`. Independently, non-final saves should at minimum drop keys not present in the definition.

### 2. TextFormat presets (cheapest high-value import in the unit)

Donor `TextFormat = z.enum(["text","email","url","phone","number","integer","alphanumeric"])` with the rationale in-file: "a closed enum rather than author-supplied regex, which would be a ReDoS surface on a server-side validator." `checkTextFormat(q, raw)` returns `string | null` — trims, then per arm: `EMAIL_RE`/`URL_RE`/`ALNUM_RE` tests; phone = `PHONE_RE` **and** 7–15 digits after `replace(/\D/g,"")`; `number`/`integer` = `Number(trimmed)` NaN check, `Number.isInteger` for integer, then `q.min`/`q.max` bounds. Camp 404's `ShortTextQuestion` (verified `:73-82`) carries only `maxLength` + `placeholder` — no format field of any kind. Port: add `format: TextFormat.optional()` + `min`/`max`, call it inside `validateOne`. **Hazard the digest flags and I confirm:** Camp 404 collapses `short_text` and `long_text` into one shared arm (`:503-509`), so the format check needs an explicit `q.kind === "short_text"` narrowing or it type-errors against `LongTextQuestion`. Bring `__tests__/questionnaire-text-format.test.ts` with it — accept + refuse for every arm plus verbatim refusal copy. **Decide first:** Camp 404 already has a distinct `number` engine kind (`:36`); adding `format:"number"` makes two ways to ask for a number. Pick one and say which in the palette.

### 3. `other:` encoding

Four exports, ~15 lines total: `OTHER_PREFIX = "other:"`, `isOtherAnswer`, `otherAnswerText`, `toOtherAnswer`. Stored value is `other:<text>` in the same flat map — no companion key, no migration, because `QuestionnaireResponses` is already `z.record(string, string|number|string[]|boolean|null)` (`:280-284`). Camp 404 has no `allowOther` anywhere (grep confirms); `single_select` rejects unknown values at `:487-492`. Three things must land together or the feature is half-broken:
- an `allowOther` flag on the choice kinds;
- the reserved-prefix **definition-time guard** (donor `questionnaire-definition.ts:231-237`), else an author can create a colliding option value;
- an arm in `displayResponseValue` (`:321-348`) — its `default:` at `:346-347` `String()`s anything unrecognised, so a stored `other:pizza` renders raw to a captain the moment this ships.

### 4. Results aggregator (the flagship, and the only L worth an L)

`packages/core/src/questionnaire-results.ts` — pure, chart-library-agnostic (returns numbers and labels only, which suits Camp 404 having no chart library). Shape: `QuestionnaireResults { totalResponses, questions: QuestionAggregate[], orphans: OrphanAnswers[] }`. `AggregateBase = { questionId, prompt, questionKind, responded, skipped, total }`, discriminated by `chart`: `choice` (`options: OptionTally[]` + `other: OtherTally[]`), `scale` (min/max/minLabel/maxLabel/buckets/average), `rating` (steps/buckets/average), `boolean` (yes/no/percentYes), `text` (`answers: string[]`), `timeline` (buckets + earliest/latest), `grid` (shared `columns` + per-row `{id,label,responded,columns}` with a per-row denominator). `OptionTally.percent` is of respondents who **answered that question**, not of everyone sent it. `aggregateResponses` walks every response's keys, and any key not in `allQuestions(definition)` and not blank becomes an `orphan` — so answers to a deleted question surface rather than vanish. Four robustness properties are stated in the module header and each is a named test: post-hoc questions report honest skips, orphans surface, deleted options still get a row labelled by raw value, out-of-range scale values keep their bucket. All four **will** occur here because `lifecycle-controls.tsx:108-119` explicitly permits editing a published questionnaire.

Two adaptation decisions to make before writing code, not after:
- **PII stance.** Donor's `chart:"text"` returns every free-text answer. Camp 404's own spec (`docs/questionnaire-builder.md:396`) says "response count only — no value breakdown — PII". Reconcile explicitly.
- **Completion denominator.** Donor's `tallyActivationCompletion` counts `waived`/`expired` as pending; `docs/questionnaire-builder.md:390` excludes them. Pick one.
- Route split: the docs reserve **two** routes, `/metrics` (:214) and `/responses` (:215) — the donor's single tabbed view maps onto both. CSV details worth not rediscovering: `\r\n` terminators, UTF-8 BOM (`new Blob([`﻿${lines.join("\r\n")}`])`, `results-view.tsx:584-585`), `""`-doubling, and `${q.id}:${o.value}` / `:row:` / `:col:` label-map keys.

### 5. Coded issues + inline placement

Camp 404's `validateBuilderQuestionnaire` (verified: signature is `(q: BuilderQuestionnaire): string[]` at `:327-330`) already checks real things — empty pages, inputs on content pages, missing alt text, <2 options, earlier-only `visibleIf` references, and a satisfiability sweep. It returns prose, so `lifecycle-controls.tsx:75-95` can only dump a list into a modal and `builder-canvas.tsx` (491 lines, **zero** validator calls and zero `useMemo` — I read the whole file) has one error surface: `toast.error(result.error)` at `:231`. Port the **issue model**, not the branch arms:

```ts
type DefinitionIssueCode = "shape" | "duplicate_id" | "reserved_id"
  | "duplicate_option_value" | "reserved_option_value" | "unreachable_page" | "invalid_range";
interface DefinitionIssue { path: string; code: DefinitionIssueCode; message: string }
type DefinitionValidation = { ok: true; definition; issues: readonly [] } | { ok: false; issues: DefinitionIssue[] }
```

Drop `unknown_branch_target`/`backward_branch`/`self_branch`/`branch_not_allowed` — Camp 404 branches by `visibleIf` and its forward-only rule already exists as the shows-when checks at `:346-350` / `:352-356`; re-express those as coded issues with paths. **Add the duplicate-id check** — it fixes two bugs, not one: `earlier` (`:339`, `:375`) is keyed by question id, so a duplicate id both collapses two blocks onto one response key **and** makes the second block's shows-when check pass spuriously. Then `definition-issues.tsx` (`issueLocation`, `sectionIssues`, `blockIssues`, `optionIssues`, dual-dialect regex for `pages[2].questions[0]` and Zod's `pages.2.questions.0.prompt`) hangs each issue on the offending control. Camp 404 already **has** Zod paths and throws them away at two sites: `questionnaire-lifecycle.ts:82-85` → "This questionnaire is malformed." and, higher-traffic, `apps/web/app/captains/questionnaires/actions.ts:137-143` on every canvas save. Also take the trivial `isValidQuestionnaireDefinition` boolean wrapper — it is the call shape a canvas `useMemo` actually wants.

### 6. Non-blocking delivery (WP4 #128 — confirmed from both ends)

The donor's card is nearly drop-in in shape: a list read (`type='questionnaire' AND status='pending'`, `createdAt desc`, carrying activationId/title/blocking/dueAt) plus an 88-line card with a per-item blocking badge, try/catch'd `toLocaleDateString("en-GB")`, and a "Complete now" vs "Answer" CTA. **Do NOT widen `getPendingRequiredActions`** — `nextGate` depends on its blocking-only contract; add a sibling read. **Do NOT** copy the donor's `parseActivationActionKey` derivation — Camp 404 stores the bare questionnaire key as `actionKey` with `activationId` in its own column (`activations.ts:108`), so select `activationId` directly and a null there is exactly what excludes the `burner_profile` code action.

## DB changes this unit implies

**Ideally none.** The donor's own rule — "everything lives INSIDE the definition jsonb, no schema columns; every field added is optional so a definition written before Builder v2 still parses" — is the right one here, and `other:`, `format`, `allowOther` and `min`/`max` all obey it. Concretely:

- `ShortTextQuestion`: `+ format?: TextFormat`, `+ min?: number`, `+ max?: number` — **JSONB only, no migration.**
- `SingleSelectQuestion` / `MultiSelectQuestion`: `+ allowOther?: boolean` — **JSONB only, no migration.**
- Six new members on the `Question` union (`multi_choice_grid`, `checkbox_grid`, `linear_scale`, `rating`, `time`, `file_link`) — **JSONB only.** Deferred; needs a renderer arm and a palette entry each.
- **Considered and NOT recommended:** a `definition jsonb` snapshot column on `questionnaire_activations` (the donor's send-time-snapshot rule). Camp 404's publish-time `questionnaire_versions` already covers the property once `classifyChange` is made order-aware; a migration plus a resolver rewrite is the expensive fix for the cheap bug.
- **Possible, if the tally needs re-send history:** `required_actions`' unique index is `(user_id, action_key)` with no per-activation row, so a re-send re-points the same row and "sent" is only reconstructable for the active activation. `docs/questionnaire-builder.md:386-388` already concedes this. Only worth a migration if the results surface must show history across sends.

Donor wraps both in `<!-- untrusted: reporter-supplied content begins -->` … `<!-- untrusted: reporter-supplied content ends -->` with `> _The rest of this issue is a user's report. **`client-errors.ts` (194 lines, zero coupling).** Ring buffer of 20 (`while (buffer.length > REPORT_LOGS_MAX) buffer.shift()`), fed by `window.addEventListener("error")`, `unhandledrejection`, and a `console.error` patch that **passes through first and unconditionally** with the whole recording body in `try {} catch {}`. `describe(value)` renders an arbitrary thrown value without throwing (JSON.stringify in a try/catch). `collectEnvironment()` returns exactly 9 device-only fields: App version, Build env, User agent, Locale, Online, Viewport (`W×H @ Nx`), Screen, Path, Timezone (in try/catch). Route is `window.location.pathname` clamped to 300 — **never** the query string; Camp 404 URLs carry `?invite=` codes and OAuth callbacks and the issue is public. Install is idempotent and returns a no-op teardown on a second call. Also take `clearClientErrors()` (backs a "don't attach these" control and test resets). Placement: `apps/web/lib/` — but note `packages/ui/package.json` *does* export `./components/*`, so the companion component could live in `packages/ui` with no exports change.

**Sanitiser merge — do not choose, merge.** Hard collision: both repos export `sanitizeReportText` from their `@*/core` barrel with incompatible returns (donor `→ RedactionResult {text, redacted}` at `report-sanitize.ts:218`; Camp 404 `→ string` at `text-redaction.ts:53`, imported by `github-feedback.ts:9` and `actions.ts`). Donor has, and Camp 404 lacks: a **depth-counting brace scanner** (`stripStructuredData`, MAX_SPAN 4000, replaces the whole balanced span with `[structured data removed]` — the regex it replaced could not cross a nested brace and published a name), UUID → `[id]`, ISO + slash dates, ref-codes, a linear `stripMarkup`, and the `RedactionKind[]` reporting channel. Keep Camp 404's secrets block first, splice the donor's ordered scalar RULES after it, and expose the new return type under a new name (`sanitizeReportTextWithReport`) or migrate the three call sites in one commit.

## Corrections applied

- **DROPPED — "latent bug: Camp 404's 13-digit ID escapes as `[phone]3` because the ID rule sits after the phone rules."** I ran the actual regexes: `redactPii("id 8801015009087 here")` → `id [id] here`. Camp 404's phone rules require `\b` at both ends, so a bare 13-digit run is not partly eaten. Rule order is still worth adopting for adjacency cases, but the stated defect does not reproduce. This claim appears in the digest's Gotchas and should not be repeated.
- **FOUND INSTEAD — a real redaction defect the digest missed.** Camp 404 has no UUID rule, and its **card rule mangles a UUID**: `3f7c1e2a-1111-2222-3333-444455556666` → `3f7c1e2a-1111-2222-[card]`, i.e. it both leaks the first half of an identifier and emits a false `[card]`. Porting the donor's UUID rule *before* the card rule fixes both.
- **TEMPERED — the `/<[^>]*>/g` "live ReDoS defect."** Measured here: 20,000 `<` = 160 ms, 50,000 = 984 ms. `actions.ts` caps description at 5,000 chars before sanitize runs, so the realistic worst case is ~10 ms. Replace it with the donor's linear scanner for correctness (it also keeps the tail after an unterminated `<`, which matters for error-log lines like `Expected count < 10`), not for availability.
- **`screenReport` is NOT effort=S standalone.** Its second argument is `readonly RedactionKind[]`, and `third-party-data` — the only flag that withholds diagnostics — is derived entirely from it. - **The corner launcher reverses a recorded decision, not an oversight.** "No floating button" appears in `design/feature-set/25-global-feedback-dialogs.md:33`, `24-nav-chrome-layout.md:99` and `design-feature-set.md`; `design/feature-set/verification/24-nav-chrome-layout.md:35` records commit `655c5e1` as literally "remove the floating button (shake-only)".

**Skeleton kit.** Nine exports, verified by grep on the donor file: `Skeleton` (:31, one `animate-pulse rounded-md bg-muted` block, `aria-hidden`, no intrinsic size), `SkeletonRegion` (:47 — the wrapper each boundary renders once: `aria-busy="true"`, `aria-live="polite"`, `data-loading="true"`, and exactly **one** `<span className="sr-only">{label}</span>`), `SkeletonText` (:68, last line `w-2/3`), `SkeletonHeading` (:92, `h-3 w-40` / `h-7 w-64 max-w-full` / `h-3.5 w-full max-w-xl`), `SkeletonCard` (:111), `SkeletonRow` (:132), `SkeletonCardGrid` (:153, default `grid gap-4 sm:grid-cols-2 lg:grid-cols-3`), `SkeletonField` (:172), `SkeletonForm` (:182). The design law (skeleton.tsx:8-13): each route composes these with **the same container classes its page uses**, so the swap is a fill, not a reflow. The test worth copying verbatim asserts one `.sr-only` per region regardless of bar count. Write the pulse as `motion-safe:animate-pulse` — already Camp 404 house style.

**ResponsiveDataTable.** `ResponsiveColumn<T>` = `{ id, header, cell: (row:T)=>ReactNode, role?: "title"|"badge"|"actions"|"default", mobileHidden?, hideHeader?, align?: "left"|"right"|"center", cellClassName?, headClassName? }` (donor :37-58). `projectColumnsToCard<T>(columns): {title, badges, actions, pairs, hidden}` (:82-115) is a pure exported function — `mobileHidden` short-circuits into `hidden` before the role switch, so it always wins; declaration order is preserved within each slot; 3 of the 11 tests hit it without React. Table props (:126-151): `columns, data, getRowKey, renderExpanded?, rowClassName?, emptyState?, caption?, className?, mobileAriaLabel?` (defaults to `caption` when caption is a plain string). Renders a real `<table>` at `md:block`, `<dl>/<dt>/<dd>` cards below. **Effort caveat (from the correction, which I accept):** Camp 404's `roster-list.tsx` is not a second declaration of the same columns — it's a deliberately different mobile board (avatar + name + a combined `@handle · flag · country` sub-line + a trailing role emoji, roster-list.tsx:61-87). The donor's card projection has no slot for that shape. So "migrate the roster onto it" means rebuilding or discarding the S17 mobile board. Land the component for the *next* table (questionnaire responses, tasks) and migrate the roster only if the board is up for revision.

**QCard (the biggest finding, and it isn't a port).** The digest's original claim — "Camp 404 has no generic Field wrapper, port the donor's `field.tsx`" — is **false**, and I confirmed it. `packages/ui/src/components/qcard.tsx` is control-agnostic (`children`), resolves `controlId = childId ?? htmlFor ?? generatedId` (:40-43), derives `${controlId}-helper` / `-error`, enforces error-supersedes-help (`describedBy = error ? errorId : helper ? helperId : undefined`, :46-47) and goes *further* than the donor by cloning the control to inject `id` + merged `aria-describedby` + `aria-invalid` (:50-61) — wiring the donor's `field.tsx` explicitly punts to the caller. `grep -rn QCard apps packages` returns **only** qcard.tsx, qcard.stories.tsx and a disambiguation comment in questionnaire-summary-card.tsx:9-10. Meanwhile `apps/web/components/questionnaire/question.tsx` renders the helper `<p>` at :60-62 with **no id**, and the error `<p role="alert">` at :71-77 with no id — neither reaches the control via `aria-describedby`. The unit-14 action is: wire QCard into QuestionField. Do not port `field.tsx`.

**Voice-recorder mic leak (confirmed against source).** `use-voice-recorder.ts`: the unmount effect at :77-93 stops `streamRef.current`'s tracks; `start()` awaits `navigator.mediaDevices.getUserMedia(...)` at :115-121 and only assigns `streamRef.current = stream` at :122. Unmount while the permission prompt is open → cleanup runs against a null ref, the promise later resolves, and the stream is assigned with nothing left to release it: the browser recording indicator stays lit until reload. The donor's `use-dictation.ts:112-121` guards exactly this ("A live microphone nobody asked for is the worst failure this hook has"). Fix: immediately after the await, `if (!mountedRef.current) { stream.getTracks().forEach(t => t.stop()); return; }` before any assignment.

**AudienceSelect.** `resolveLine(count, noun)` (:41-45): `0` → `Resolves to no ${noun} yet`; `1` → `Resolves to ~1 ${noun.replace(/s$/,"")}`; else `Resolves to ~${count} ${noun}`. Hidden when `resolvedCount` is `null` **or** `undefined` (:58) so a pre-selection state shows nothing, never a misleading "0". The law (:16-18): the component resolves nothing — one resolver server-side, one display. Camp 404 wiring correction: `resolveAudience` (`packages/db/src/broadcasts.ts:52`) takes a broadcast row `{id, scope, team}` and is called only from :260/:342 — it cannot be pointed at a questionnaire send as-is. The questionnaire path reads membership at `packages/db/src/activations.ts:68-70`; build the count action there. Pair it with a disabled Send at count 0 to close WP6 (#130).

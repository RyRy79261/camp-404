## §0 — Five cross-cutting facts that change what several units concluded

**0.1 `team_memberships` has no production write path.** Independently verified by units 03, 04, 08, 09, 14, 15, 17, 22: the only `insert(schema.teamMemberships)` anywhere is `packages/db/src/__tests__/_factories.ts:39`; `packages/db/src/account.ts:96` only DELETEs. Consequences, all of which are currently invisible: every `team` / `team_leads` broadcast and questionnaire send resolves to **zero recipients and toasts success**; a wrangler/officer coverage card would ship permanently 0-of-8 (unit 17); `busiestLoad` cannot be observed; the safety-data predicate's `team_lead` branch is inert (unit 22); the e2e persona registry's `team_lead` row documents a stranded tier (unit 19). **This is the single highest-fanout blocker in the corpus, and it is not a donor port** — it is Camp 404 work for which the donor's `AssignRolesDialog` (unit 07, `apps/web/components/camp-members.tsx:227-315`) is the reference UI.

**0.2 `AGENTS.md:180-182` says the Playwright suite is disabled; `ci.yml:179` runs it on every `src` PR.** Unit 21 verified both sides; unit 20 confirms the e2e job is inside the `ci-pass` aggregate at `:218`. Units 01, 02, 06, 09 and 23 each **downgraded e2e items on the false premise that the suite is dead**. Any e2e recommendation in those units should be re-read at full value. This contradiction is exactly what unit 21's `UNRESOLVED (flagged <date>)` marker is for — the maintainer's call, not a guessed rewrite.

**0.3 Every `WP1…WP12` / `#125…#136` reference is unverifiable from the working tree.** Units 09, 12, 16 and 19 each grepped `DEFERRED.md`, `AGENTS.md`, `docs/` and `design/` and found nothing; the GitHub MCP server failed to connect this session. Unit 21 states there are 12 open issues numbered #125–#136. Treat every "already planned in WPn" as an **external tracker pointer with no in-repo evidence**. The two asks that *are* citable verbatim are `DEFERRED.md:71` (redirect-ladder consolidation) and `DEFERRED.md:66` (invite-code case handling).

**0.4 The `loading.tsx` rollout is spec-blocked, and only unit 18 noticed.** Twelve units treat "zero `loading.tsx` across 24–26 force-dynamic pages" as a straight gap. Unit 18 found six Camp 404 impl specs that say **do not create one**: `16-captain-tools.md:43`, `11-invite-tool.md:57`, `09-notifications.md:153`, `05-approval-gate.md:54`, `01-landing.md:27`, `17-mcp-connect.md:125`. `design/spec/flows.md:440` is the narrower defensible position — server pages arrive complete; skeletons are for *client* fetches. **The kit is unconditional; the rollout needs a decision.** Ship the primitives, scope their use to client-fetch surfaces, and keep `data-loading="true"` regardless (it serves the a11y/e2e half either way).

**0.5 Two of the highest-value items are live data-destruction bugs, not feature gaps.**
- Unit 23: the questionnaire builder's `image` kind renders `AvatarUpload` with no `uploadUrl`, so it writes `avatars/<uid>/` and fires `deleteAvatarBlobs`, which `del()`s everything else under that prefix. **A questionnaire image answer deletes the member's profile photo, and vice versa.** Effort S.
- Unit 12: `idColumnsFor` nulls the non-matching ID column unconditionally, and `decryptOrNull` reports unreadable ciphertext as absent — so **one ordinary re-save on a key-rotated deployment permanently overwrites a member's encrypted SA ID with `null` under a "Saved" toast.** Effort S once `decryptField` lands.
